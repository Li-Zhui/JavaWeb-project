一、单元测试
    1.单元测试：就是针对最小的功能单元(方法），编写测试代码对其正确性进行测试。

    2.JUnit：最流行的JaVa测试框架之一，提供了一些功能，方便程序进行单元测试（第三方公司提供）。

    3.main方法测试的缺点
      3.1 测试代码与源代码未分开，难维护
      3.2 一个方法测试失败，影响后面方法
      3.3 无法自动化测试，得到测试报告

    4.JUnit单元测试的优点
      4.1 测试代码与源代码分开，便于维护
      4.2 可根据需要进行自动化测试
      4.3 可自动分析测试结果，产出测试报告

三、断言
    1.元测试运行不报错（绿色），不能代表代码没问题
      测试通过只能说明，测试方法编写的没有问题，
      不代表被测试业务方法的逻辑没有问题。

    2.什么是断言？
        JUnit提供了一些辅助方法，用来帮我们确定被测试的方法是否
        按照预期的效果正常工作，这种方式称为断言。

    Assertions.assertEquals(object exp, Object act, String msg)
        检查两个值是否相等，不相等就报错。

    Assertions.assertNotEquals(object unexp, Object act, String msg)
        检查两个值是否不相等，相等就报错。

    Assertions.assertNull(object act, String msg)
        检查对象是否为null，不为null，就报错。

    Assertions.assertNotNull(object act, String msg)
        检查对象是否不为null，为null，就报错。

    Assertions.assertTrue(boolean condition, String msg)
        检查条件是否为true，不为true，就报错。

    Assertions.assertFalse(boolean condition, String msg)
        检查条件是否为false，不为false，就报错。

    Assertions. assertThrows(class expType, Executable exec, String msg)
        检查两个对象引用是否相等，不相等，就报错。

    3.提示：上述方法形参中的最后一个参数msg，
      表示错误提示信息，可以不指定（有对应的重载方法）。

    4.小结
        在JUnit单元测试中，为什么要使用断言？
            单元测试方法运行不报错，不代表业务方法没问题。
            通过断言可以检测方法运行结果是否和预期一致，从而判断业务方法的正确性
            Assertions.assertXxxx(...)


四、常见注解
    1.在JUnit中还提供了一些注解，还增强其功能，常见的注解有以下几个:
        注解                              说明                                      备注
        @Test                   测试类中的方法用它修饰才能成为测试方法，            单元测试
                                才能启动执行

        @ParameterizedTest      参数化测试的注解（可以让单个测试运行多次，          用了该注解，就不需要aTest注解了
                                每次运行时仅参数不同）

        @Valuesource            参数化测试的参数来源，赋予测试方法参数             与参数化测试注解配合使用

        @DisplayName            指定测试类、测试方法显示的名称（默认为类名、方法名）

        @BeforeEach             用来修饰一个实例方法，该方法会在每一个测试方法执行   初始化资源(准备工作)
                                之前执行一次。

        @AfterEach              用来修饰一个实例方法，该方法会在每一个测试方法执行   释放资源(清理工作)
                                之后执行一次。

        @BeforeAll              用来修饰一个静态方法，该方法会在所有测试方法之前     初始化资源(准备工作)
                                只执行一次。

        @AfterAll               用来修饰一个静态方法，该方法会在所有测试方法        释放资源(清理工作)
                                之后只执行一次。

    2.小结
      2.1 JUnit单元测试的方法，是否可以声明方法形参？
            可以的，参数化测试
            @ParameterizedTest + @ValueSource
      2.2 如何实现在单元测试方法运行之前，做一些初始化操作？
            @BeforeEach、@BeforeAll
      2.3 如何实现在单元测试方法运行之后，释放对应的资源？
            @AfterEach、@AfterAll
