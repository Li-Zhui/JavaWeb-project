=======================================一、分模块设计与开发============================================
1.为什么？
    将一个大项目拆分成若干个子模块，方便项目的管理维护、扩展，也方便模块间的相互引用，
    资源共享。



2.分模块设计一策略

    2.1 策略一：
        按照功能模块拆分，比如：公共组件、商品模块、搜索模块、购物车模块、订单模块等。

    2.2 策略二：
        按层拆分，比如：公共组件、实体类、控制层、业务层、数据访问层。

    2.3 策略三：
        按照功能模块+层拆分。



3.步骤
    a.创建maven模块 tlias-pojo，存放实体类。
    b.创建maven模块 tlias-utils，存放相关工具类。



4.注意：
    分模块开发需要先针对模块功能进行设计，再进行编码。不会先将工程开发完毕，然后进行拆分。






=======================================二、继承-继承关系============================================
1.介绍

    1.1 概念：
        继承描述的是两个工程间的关系，与jaVa中的继承相似，子工程可以继承
        父工程中的配置信息，常见于依赖关系的继承。

    1.2 作用：
        简化依赖配置、统一管理依赖

    1.3 实现：
        <parent>...</parent>



2.打包方式：

    2.1 jar:
        普通模块打包，springboot项目基本都是jar包（内嵌tomcat运行）

    2.2 war：
        普通web程序打包，需要部署在外部的tomcat服务器中运行

    2.3 pom：
        父工程或聚合工程，该模块不写代码，仅进行依赖管理



3.继承关系实现

    3.1 创建maven模块tlias-parent，该工程为父工程，设置打包方式pom（默认jar）。

    3.2 在子工程的pom.xml文件中，配置继承关系。

    3.3 在父工程中配置各个工程共有的依赖（子工程会自动继承父工程的依赖）



4.<relativePath>标签

    4.1 作用：
        配置父工程pom.xml的相对地址

    4.2 什么都没配置且自闭合（<relativePath/>）：
        表示将本地仓库查找这项依赖，本地仓库没有从中央仓库查找



5.注意：

    5.1 在子工程中，配置了继承关系之后，坐标中的groupId是可以省略的，
        因为会自动继承父工程的。

    5.2 relativePath指定父工程的pom文件的相对位置（如果不指定，
        将从本地仓库/远程仓库查找）。

    5.3 若父子工程都配置了同一个依赖的不同版本，以子工程的为准。






=======================================三、继承-版本锁定============================================
1.介绍
    在maven中，可以在父工程的pom文件中通过<dependencyManagement>
    来统一管理依赖版本。

    1.1 定义：
        <dependencyManagement>

            <dependencies>

                <dependency>
                    <groupId>io.jsonwebtoken</groupId>
                    <artifactId>jjwt</artifactId>
                    <version>0.9.1</version>
                </dependency>
                ...

            </dependencies>

        </dependencyManagement>



2.自定义属性/引用属性

    2.1 定义：
          <properties>
              <spring.boot.version>3.5.7</spring.boot.version>
              <lombok.version>1.18.42</lombok.version>
              ...
          </properties>

    2.2 使用：
        通过 ${自定义属性名} 的形式使用
        <version>${lombok.version}</version>



3. <dependencyManagement> 与 <dependencies>的区别是什么?

    3.1 <dependencies>：
        是直接依赖，在父工程配置了依赖，子工程会直接继承下来。

    3.2 <dependencyManagement>：
        是统一管理依赖版本，不会直接依赖，还需要在子工程中引入所需依赖（无需指定版本）






=======================================四、聚合============================================
1.问题：
    原先的 Maven 打包操作（package）必须将当前模块所需要的所有依赖
    提前安装（install）到本地仓库，显得十分繁琐。



2.解决——Maven的聚合：

    2.1 介绍：
        将多个模块组织成一个整体，同时进行项目的构建（编译、安装、打包等）。

    2.2 聚合工程（一般聚合工程和父工程为同一项目）：
        一个不具有业务功能的“空”工程（有且仅有一个pom文件）

    2.3 作用：
       快速构建项目（无需根据依赖关系手动构建，直接在聚合工程上构建即可）

    2.4 实现：
        maven中可以通过<modules>设置当前聚合工程所包含的子模块名称

    2.5 例子（在父工程/聚合工程中）：
        <!--聚合-->
        <modules>
            <module>../tlias-pojo</module>
            <module>../tlias-utils</module>
            <module>../tlias-web-management</modula>
        </modules>



3.注意：
    聚合工程中所包含的模块，在构建时，会自动根据模块间的依赖关系设置构建顺序，
    与聚合工程中模块的配置书写位置无关。



4.maven中继承与聚合的联系与区别 ？

    4.1 联系：
        继承与聚合都属于设计型模块，打包方式都为pom，常将两种关系制作到同一个pom文件中。

    4.2 区别：
        继承用于简化依赖配置、统一管理依赖版本，是在子工程中配置继承关系
        聚合用于快速构建项目，是在父工程（聚合工程）中配置聚合的模块






=======================================五、私服-介绍============================================
1.简介
    私服是一种特殊的远程仓库，它是架设在局域网内的仓库服务，用来代理位于外部的中央仓库，
    用于解决团队内部的资源共享与资源同步问题。



2.依赖查找顺序：
    本地仓库 -> 私服 -> 中央仓库



3.注意：
    私服在企业项目开发中，一个项目/公司，只需要一台即可（无需我们自己搭建，会使用即可）。






=======================================六、私服-资源上传与下载============================================
1.私服常见三类仓库、

    1.1 release仓库：
        （发行版）：功能趋于稳定、当前更新停止，可以用于发行的版本，存储在私服中的RELEASE仓库中。

    1.2 snapshot仓库：
        （快照版本）：功能不稳定、尚处于开发中的版本，即快照版本，存储在私服的SNAPSHOT仓库中。

    1.3 central仓库：
        从中央仓库中下载的jar包存放在这个仓库中

    1.4 注意：
        版本号只要不是snapshot就会放在Release中



2.上传资源到私服的步骤：

    2.1 将需要上传的模块安装（install）到Maven本地仓库

    2.2 在本地仓库配置两套（snapshot和release）访问私服的用户名和密码
        （Maven的settings.xml中的servers中配置）

    2.3 在IDEA的 Maven项目 中配置两套（snapshot和release）上传资源的位置（url地址）
        （pom.xml文件配置上传地址）

    2.4 再执行生命周期中的部署（deploy）就会将这个模块传到私服



3.从私服下载资源的步骤：

    3.1 在本地仓库配置私服依赖下载的地址（url地址）
        （Maven的settings.xml中的mirrors、profiles中配置）

    3.2 配置profiles的原因：
            默认私服不允许访问snapshot这个不稳定版本的仓库
            这里就是配置允许访问私服快照版本仓库

    3.3 然后从私服下载到本地仓库，最后在项目中就可以关联到本地仓库的依赖了
